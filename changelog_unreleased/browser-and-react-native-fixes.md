### Fixed
- **Browser and React Native — a refused batch is no longer silent.** When the ingest endpoint answers 401 or 403, the SDK warns on the console once, even with `debug` off, so a wrong `apiKey` or `dsn` no longer looks like a working SDK. Any other non-2xx response is logged with its status when `debug` is on.
- **Browser and React Native — `data:` and `blob:` URLs are no longer captured as network requests.** They are read from memory, not the network. A large `data:` URL, such as an image preview an app reads with `fetch`, used to be copied into every URL field of its event and could freeze the page.
- **Browser and React Native — an out-of-range `sessionMaxDuration` in `updateConfig` keeps the current cap.** It used to reset the cap to the 4-hour default, undoing the value the app chose at `init`. The warning now names the cap in use. Flutter, iOS and Android already behaved this way.
- **React Native — a native crash report survives an `enrichEvent` hook that throws partway.** The hook now gets a copy of the crash event, so one that changes it and then throws no longer ships its half-done changes in place of the report.
