### Changed
- **Browser — a visit the user leaves before interacting is no longer always lost.** The SDK sends nothing for a visit until the user first interacts with the page, and dropped what it held if they never did: a page that loaded slowly and was reloaded or left before it was used, or one that threw while loading, left nothing behind. Now, when the page is hidden or closed, a visit with no interaction yet is sent, with everything the SDK held for it (page load, network requests, logs, errors), if the page was visible at some point or the visit caught a real exception (uncaught error, unhandled rejection or `captureException`; not `Script error.` or the ResizeObserver loop notices). Tabs opened in the background and closed unseen, pages reloading themselves in a background tab, and prerendered pages nobody opened are still dropped, and nothing is sent while the page is open. Every visible visit the user leaves without interacting, bounces included, now appears as a session, and so do bots that close their pages normally.

### Fixed
- **Browser — the batch sent when a visitor leaves the page now arrives.** The SDK sends what it holds when the page is hidden, but when the visitor navigated away or closed the tab, the browser often cancelled that request before the batch went out, losing the events captured since the last send (up to `transport.batchTimeout`, 10 seconds by default). It is now sent as a `keepalive` request, which outlives the page. A batch over the browsers' 64 KiB keepalive limit is sent as before. That limit is shared with the app's own keepalive requests, so only this send uses it, and a request the browser refuses is sent again once without `keepalive`.
- **Browser — what the page reports as it is hidden goes out with that send.** The send ran before page-hide listeners added after the SDK started, so the final Core Web Vitals (CLS, INP and LCP are reported when the page is hidden), replay frames still waiting for their batch, and errors thrown in the app's own hide handler were left behind, and lost if the page closed. They now go with it.
- **Browser — closing a tab that is already in the background now sends what it held.** Such a tab gets no visibility change when it closes, so nothing was sent. The SDK now also sends on `pagehide`.
- **Browser and React Native — an event captured while a batch was being sent is no longer lost or sent twice.** For example, a log written by a `fetch` wrapper the app installed.
